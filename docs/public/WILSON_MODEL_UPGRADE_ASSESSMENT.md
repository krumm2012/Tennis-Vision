# Wilson 模型与握拍约束升级评估

检查日期：2026-09-29。范围：本地模型结构、当前250帧拟合统计、升级方案；未替换现有结果或重跑人体推理。

## 模型实检

| wilson_blade_team_tennis_racket-2.glb | 1,734,852 | 14,664 | 三张1024² |

两个GLB访问器引用的几何数据哈希一致；含拍框、拍线、深色部件三组网格及三种材质。资产元数据标记作者 Ya、来源 Sketchfab、SKETCHFAB Standard。GLB结构和纹理已直接解析；Blend文件已找到，但未在Blender中打开核验。建议GLB小版本用于交互显示，大版本保留作离线输出素材。

原始几何长轴Z，拍面在XZ平面，厚度沿Y；拍头在负Z侧，柄尾在正Z侧（由独立拍线网格范围判定）。父节点两次相反旋转合成单位旋转，但导入时仍应遍历全部节点，不能只忽略层级读取顶点。原始长度8.871507，宽3.367258，厚0.497875，不能直接当作米。

若暂沿用现有0.685m长度，统一缩放后宽约0.260m、最大厚度0.0384m。此长度为项目假设，未测量实物。保持模型比例；现有0.270m宽椭圆与新模型并不完全一致，应重新提取拍框轮廓而不是只更换贴图。

建议标准轴：柄尾为原点，+Y指向拍头，X横跨拍面，Z为拍面法向。对当前合成节点变换后的顶点，初步映射为 (x, z_max-z, y) 再统一缩放；该旋转保持右手坐标。握持中心、柄尾、喉部、拍头、两侧边缘及拍面法向存入独立锚点配置，并在模型预览中人工确认。

## 握持一致性问题

fit_racket_pose.py与fit_racket_video.py均使用局部[0,0.115,0]作为握持点，并直接约束到SAM右手腕41。真实握持中心位于掌内，手腕与握持中心不能等同。现有原始手关节中，腕到食指/中指近掌关节28/32的中位距离约7.7/7.5cm（模型尺度），足以显著影响拍柄位置。

当前250帧握持点到手腕距离：中位3.6cm、P90为9.4cm、最大20.7cm；78帧超过5cm，20帧超过10cm。这些是现有错误目标下的内部残差，不是实际抓握精度。

升级应以腕41、近掌指关节28/32/36/40建立手掌坐标系，在清晰握拍帧估计掌内握持中心和柄轴方向。对持续持拍片段固定或缓慢变化“手掌到拍柄”的相对变换；换握、松手、双手辅助时分段处理。手掌局部偏移需由画面验证，不能简单用指关节均值代替真实握点。低质量或遮挡帧降低手指约束，使用相邻可靠帧推断，并标记不确定性。

当前显示平滑姿态时，racket_renderer.js仅补偿手腕平移，没有补偿手掌旋转。升级显示层需要用当前姿态模式的手掌坐标系同步握持锚点与朝向，避免人体平滑后球拍仍保留原始手部旋转。手腕允许弯曲，不能把拍柄固定成前臂的延长线。

## 拍面角度问题

目前仅以拍头椭圆、软手腕约束和邻帧选择估计旋转；轮廓不足以唯一确定空间拍面。现有153帧轮廓拟合、97帧插值。相邻帧完整旋转超过45°有8处，但完整旋转混合了挥拍指向和拍面转动，不能直接解释为8次拍面翻转。

按法向正负等价计算拍面平面夹角：中位4.4°、P95为31.0°、最大50.6°/帧。拍柄轴方向相邻变化中位3.6°、P95为38.3°、最大150.5°/帧。25fps下这些是复核信号，不是实际角速度测量。

建议联合约束真实Wilson拍框轮廓、掌内握持中心、柄轴、真实与镜中同一物理关键点以及时间连续性；同时保留多个可能朝向，在整段动作中选连续解。镜面参数为估计值，需要将其误差纳入权重。优先复核Viewer帧32、42、48、59、153、161、164、171，以及60–89附近的偏移段。

continuous_plane当前利用对称外观把绕柄轴180°旋转当作等价解。带Wilson文字和正反面细节的新模型不能逐帧任意切换这一标记方向。应区分无符号平面角与有符号材质朝向；根据可见标志或已确认关键帧固定分支，没有证据时保留不确定标记。

## 实施顺序及验收

1. 导入轻量GLB，烘焙节点变换、统一尺度，提取并确认锚点；建立模型三视图及五点重投影预览。
2. 增加手掌坐标和握持偏移标定；先验证约10–15个覆盖准备、引拍、加速、随挥的清晰帧，保存掌柄距离与柄轴偏差。
3. 用真实拍框轮廓及镜中观测联合拟合，分开统计握持误差、拍柄方向变化和拍面角变化；处理正反面分支。
4. 再处理250帧并导出实拍对比；使用未参与标定的手工关键帧评估重投影误差，逐一核对当前8个大跳变和插值段。不得以模型外观改善或残差下降替代真实准确率。

GPU：以上模型规范化、锚点/掌柄约束、现有数据重拟合和导出可在本机完成。只有需要重新运行SAM 3D Body手部推理，或批量补充高分辨率真人/镜中球拍检测跟踪时，才需要重新评估云GPU；届时说明输入、显存和预计工作量后通知用户开启。当前无需开启云GPU。

## 2026-09-29 本轮实现与验收

已实现 prepare_wilson_model.py、fit_wilson_sequence.py、audit_wilson_upgrade.py；Viewer支持Wilson几何及上一版对比。GLB原节点变换已烘焙，基础颜色按UV采样成顶点颜色供现有WebGL渲染使用（不是完整PBR材质加载器）。模型保持14,664个三角面，柄尾原点、+Y拍头方向，握点暂设距柄尾0.10m。模型三视检查输出为wilson_model_anchors.png。

关键帧自动候选为Viewer帧8、42、117、125、152、165、194、250。检查图wilson_keyframes_review.jpg已经生成并查看；42和152有运动模糊，不宜当作精确真值。共享掌内偏移拟合触及约束边界，未接受为可靠标定；当前回退为手掌局部[0,0.04,0]m的解剖初值，文件明确标记provisional_anatomical_prior和requires_manual_confirmation。第二阶段只完成了自动初值和复核资料，真实抓握标定尚未完成，不能报告为已确认。

全片250帧已重算。149帧通过轮廓筛选，101帧标记为掌柄及时序约束估计；44帧使用自动关联的镜中拍头候选（并非人工验证对应点）。拍柄握点固定在所估计的掌内目标上，其零约束残差是数学构造，不能视为实际握持精度。平滑姿态显示时同时补偿手掌平移和旋转。

最终保留权重版本：相邻旋转>45°从8处降到3处（42、48、147），最大角变化151.5°降到118.1°。轮廓误差中位4.33→4.56px，P90为15.80→8.70px。新旧使用不同轮廓/观测集合，不能将这些数字直接当作准确率比较。更强平滑版本虽消除>45°跳变，但引拍段偏离实拍明显，已弃用并单独保存为racket_poses_v2_oversmoothed_rejected.json。

现有racket_poses.json指向本轮实验结果；racket_poses_v1.json保留上一版，Viewer按钮可切换对比。两项掌坐标几何测试、五项既有球拍拟合测试、左右方向回归及JS语法检查通过。新的真实视频vs俯视Wilson模型视频为real_vs_wilson_v2_overhead.mp4（2000×720，25fps，250帧）；浏览器交互未复测，此前该页面导航被浏览器安全策略阻止，本轮通过本地离线渲染验收模型与视频输出。未做远端发布。

下一步精确化所需证据：实物球拍尺寸、关键帧掌内握持点/柄尾/拍头的可靠标注，以及镜中对应点。云GPU不是当前缺口；现有全部计算已在本机完成，无需开启云GPU。
