# Viewer 左右、上下与俯视相机：修改评估

日期：2026-09-26。范围：当前 `output/sam3d_cloud/viewer.html` 与 `mesh_renderer.js`。本次只评估和记录，不修改显示行为。

## 结论

不能由“摄像头俯视、正对人”推导出“SAM 三维人体必须左右镜像”。俯视对应相机俯仰；面对相机时，人的解剖学左侧通常出现在观察者的画面右侧。这是观察视角差异，不是模型左右一定错误。

建议先增加“原相机视角”作为核对基准，再增加默认关闭的“左右镜像显示”开关满足镜像教学需求。不能将镜像显示称为恢复真实人体左右。若实际问题是人物背面/正面观察方向相反，应旋转视角180度，而不是反射几何。上下方向单独由地面法向和相机俯仰控制。

还没有以已知左/右手动作独立验证解剖标签，也没有确认原始录像设备是否启用了镜像保存；这两点不能靠模型自身投影一致性判断。

## 代码证据

1. `prepare_mesh.py` 保存相机坐标原始网格、骨盆中心和相机平移；原相机投影为 `u=640+f*X/Z, v=360+f*Y/Z`。相机坐标约定是 X 向画面右、Y 向画面下、Z 向相机前方。
2. `viewer.html` 的 `rotate()` 与 shader 的 `basis*displayPosition` 都实现地面基底的转置乘法：JS 按列点乘，WebGL 将 `basis.flat()` 按列主序读取。两者不是一处漏转置。
3. 保存的实测地面基底与估计基底行列式均约为 +1，是旋转，不含左右反射。实测基底的向上轴约为 `(0.03495,-0.88732,-0.45982)`，考虑了相机俯视，与简单“相机Y取负”不同。
4. 网格的最终虚拟视角为正交投影，通过 yaw/pitch 控制；不是原相机的透视投影。当前“正面视角”硬编码 yaw=π、“背面视角”硬编码 yaw=0，两者 pitch=0.2。按钮名称并未根据每帧身体朝向自动判断，运动转身时不能保证仍为人体正面/背面。
5. `UNPACK_FLIP_Y_WEBGL` 配合纹理 `v=.5-f*Y/(720*Z)` 是图像行方向转换，不是左右镜像，也不是人体倒置。
6. 原相机贴图、镜面反射和最终观察相机是不同步骤。镜面使用 `P'=P-2(n·P-d)n`；这个物理反射不应再用整体左右翻转代替。
7. 官方本地源码 `output/cloud_backup_20260926/sam-3d-body/sam_3d_body/metadata/mhr70.py`：5/6为左右肩、62/41为左右腕；Viewer的左右骨架集合与这几个关键索引一致。不能仅为交换屏幕两侧而交换关节名称。

### 数值检查

检查250帧全部关键点的“3D+相机平移→2D”投影，与保存的SAM二维结果比较：

- 原投影误差中位数约0.0000187像素。
- 仅水平翻转投影后，误差中位数约319.75像素（按连续图像坐标 u'=1280-u）。
- 结果文件：`output/sam3d_cloud/orientation_assessment.json`。

这仅说明当前相机投影内部一致；不是独立标注，也不能证明人体左右预测正确。镜像显示时如果视频和二维叠加一起变换，当然仍能保持显示一致，但那是显示约定改变。

## 方案A：原相机视角，优先实施

添加“原相机”“地面观察”“人体跟随”视角类型，保留原始关节和标定数据。

- 原相机模式使用真实焦距、主点、源相机平移和透视投影；视口按1280:720适配并处理留白。
- 核对时使用原始网格及原始相机位置。地面锚定/平滑/镜像优化模式可能改变人体位置，不能把变换后的网格直接当成原相机重投影真值。
- 若要同时投影实测地面和人体，明确统一的相机—地面刚体/尺度变换及其逆变换，避免重复添加骨盆平移。
- 不凭 pitch=0.2 猜相机俯角；相机模式直接使用原相机坐标与内参。
- 用L/R关节标注和地面“AB方向/上/AD方向”轴区分人体左右与场地坐标。地面+X沿AB，不等于运动员始终的右手侧。

“人体跟随”应从双肩/髋和朝向线索构造随人转动的正交基，处理转身和遮挡时的180度歧义与时序连续性；它仍是旋转，不能用反射替代。

## 方案B：左右镜像显示，独立可选

适用于用户希望“像照镜子练动作”的视觉效果。只在最终观察投影后翻转屏幕水平轴：

```text
WebGL显示通道：clip.x *= displayMirror ? -1 : 1
2D骨架/地面/轨迹：screenX = displayMirror ? viewportWidth-screenX : screenX
```

实施要求：

- 开关命名“左右镜像显示”，默认关闭；与“镜中背面纹理”完全分开。
- 最终显示网格、骨架、地面、轨迹、方向轴同时翻转；文字在最终锚点正常绘制，不能把文字本身反写。
- 原视频面板默认保留原图作为核对依据，清晰提示3D已镜像。若提供视频同步镜像，视频、二维骨架、选点、鼠标坐标全部统一映射；保存标定时必须逆变换回原始像素坐标。
- `sourcePass=1/2` 的源/镜像深度投影不翻转；`originalCamera`、纹理UV、mask、镜面参数和邻帧纹理来源不变。
- 全帧覆盖统计的目标观察投影跟随镜像。理论可见面积及权重不变，但160×120采样可能有小的栅格差异，使用容差比较。
- 拖动的水平角度增量按显示方向调整，确保鼠标跟手；正/背面与重置按钮保留镜像开关状态，并明确各自语义。
- 镜像显示有反射的手性，不能将其输出当作改变后的真实解剖坐标；导出的姿态继续保持原始坐标约定。

不建议直接CSS翻转整个页面或仅翻转WebGL画布：容易让地面、文字、二维骨架、标定点击和旋转交互不同步。

## 不建议：直接将SAM的X取负

若把所有源坐标改为X取负，就必须同步修改相机投影、根平移、镜面法向、地面变换、法线/三角形绕序以及有关缓存。正交坐标变换Q下平面满足 n'=Qn；带平移t时 d'=d+n'·t。仅改顶点会破坏贴图对应。行列式为-1的变换还会影响旋转、叉积和有符号角度的解释。

只有独立证据确认输入录像镜像且确需统一坐标规范时，才设计完整的数据迁移，并版本化保存；不应为显示偏好改写推理数据。

## 验收步骤

1. 选择能明确识别手部的帧，用用户已知的举左手/持拍手和原视频文字方向确定输入是否镜像；不能假定运动员惯用手。
2. 原相机模式叠加左右肩、腕、髋和网格轮廓，确认投影与原视频同向；上下检查地面法向、脚接地点与人体高度。
3. 旋转180度时，屏幕左右变化而关节L/R身份不变；水平镜像时，不改变源数据或镜面标定。
4. 在原始、平滑和镜像约束姿态，以及各定位模式中验证开关；校准重载、拖动、缩放、导出都应一致。
5. 对250帧复核视频贴图、深度拒绝与覆盖率；镜像开关前后应在栅格采样容差内一致，不以覆盖率替代左右标签正确性验证。
6. 比较模型、标定和贴图文件校验值，确认显示开关不改写源数据。

实施顺序：原相机核对视角与坐标标签 → 可选左右镜像显示 → 人体朝向跟随。当前文件仅记录评估，Viewer尚未启用镜像显示。

## 后续定位：最终观察深度符号问题

用户明确给定：真人面对相机、右手持拍显示在图像左侧；镜中同一右手显示在图像右侧。此处的左右是所述姿态下的屏幕位置，运动中手跨过身体时不应固定用屏幕位置判断解剖左右。

### 坐标流程

```text
真人原视频 → SAM关节/网格（相机X右、Y下、Z前）
  ├─ 原相机投影 → 原视频纹理与二维关节
  ├─ 镜面几何反射 → 镜中纹理/遮挡/关节约束
  └─ 骨盆居中 → 地面基底转换 → 定位平移 → yaw/pitch旋转
       → 最终屏幕XY + 深度测试 ← 此处发现方向问题
```

### 已确认的源数据证据

- 第1帧左/右肩图像X约904.16/850.54，左/右腕约887.40/858.37。
- 第183帧左/右肩X约814.41/764.71，左/右腕约788.73/729.84。
- 这两个正面帧中右肩、右腕在画面左侧，与用户描述一致。此为关键点位置核对，未独立检测球拍或人工审阅每帧持拍接触。

### 核心问题：可见面与屏幕左右不一致

当前地面基底的+X近似相机向右，+Y向上，+Z近似朝向相机（相机坐标约`(0.04119,0.46099,-0.88645)`）。因此默认面向原相机的观察应位于地面+Z一侧。

但 shader 最终观察投影是：

```glsl
float x = p.x*cos(yaw) + p.z*sin(yaw);
float z = -p.x*sin(yaw) + p.z*cos(yaw);
float y = p.y*cos(pitch) - z*sin(pitch);
float depth = p.y*sin(pitch) + z*cos(pitch);
gl_Position = vec4(x*..., y*..., depth/20., 1.);
```

配合 `DEPTH_TEST`、`LEQUAL`，较小的depth更靠前：yaw=0时，世界-Z一侧被视为靠近观察者，实际优先显示背面，而屏幕X仍沿世界+X。对通常的右手坐标、Y向上的相机观察，这缺少投影深度的负号，形成与正常观察相反的可见面选择。

目前“正面视角”设置yaw=π，借由反向深度看到了正面，但同时 `screenX=-worldX`，因此出现“脸朝前了，持拍左右却反了”。“背面视角”yaw=0则对应相反组合。这与用户描述的方向问题吻合，不能仅靠再加一个镜像显示开关掩盖。

这修正了前文“优先新增相机视角”的排序：应先修复最终观察投影的手性/深度约定，再新增可选视角。此前基底det=+1和源投影一致性的检查是成立的，但不足以证明最终Viewer的观察方向正确。

### 镜像左右对应单独核查

当前镜像MediaPipe结果与SAM使用交换标签配对：SAM右腕41→镜像检测left_wrist15，SAM左腕62→镜像检测right_wrist16。它是对反射图像中的模型标签的对应约定，不是现实右手变成左手，也不应再次交换SAM的解剖标签。

固定当前镜面参数、不重新拟合，1962个置信度>0.75的对应点：

|匹配方式|全部点误差中位数|SAM右腕对应误差中位数|
|---|---:|---:|
|同名匹配|27.45 px|28.97 px|
|当前交换匹配|7.31 px|14.05 px|

结果文件：`output/sam3d_cloud/coordinate_flow_check.json`。当前镜面本身使用交换配对拟合，因此比较有拟合偏向，不能据此独立证明镜像检测标签总是正确。当前证据不支持直接取消交换；仍需对无遮挡持拍帧人工核对镜中手腕。代码旧注释“Anatomical labels swap under reflection”过于绝对，应改为“反射图像检测标签与源人物解剖标签的对应”，现实解剖身份不变。

### 建议修复（本次仅分析，尚未实施）

1. 将最终观察通道改为 `gl_Position.z=-depth/20.`；仅改sourcePass=0，原相机/镜像深度通道仍使用sourceClip原公式。
2. 配套将正面预设改为yaw=0、背面预设改为yaw=π。该命名仅适用于当前起始朝向，更稳妥是“原相机侧/镜子侧”。
3. **实施时更正**：保持原公式 `y=p.y*cos(pitch)-z*sin(pitch)`、`depth=p.y*sin(pitch)+z*cos(pitch)`，最终clipZ取负。此时正pitch的观察者位于上方。此前建议同时反转俯仰项不正确，会使正pitch变为仰视；2D project()和简化人体camera()原公式已一致，无需改动。
4. 简化人体画家算法按变换后的向观察者深度升序绘制（远→近），替换当前降序。骨架线没有完整遮挡测试，不宜据此单独判断前后。
5. 复核鼠标旋转、光照法线、地面和轨迹，保持2D/3D同一观察变换。标定、原始SAM数据和纹理UV不需要改写。
6. “背面固定视角”审计也需更新视角定义。旧13.57%是在旧观察约定下采样，不可直接宣称修复后数值等价；新的背面画面/俯仰变化会改变可见区域，应保留旧报告并重新审计。

验收核心：选定明确右手持拍帧，原相机侧显示脸且右腕在画面左侧；镜子侧显示背且同一右腕在画面右侧；L/R身份全程保持不变。正俯仰应看到地面上表面，旋转后前后遮挡符合物理关系。完成这些，再考虑额外的镜像教学开关。

全帧审计改为背面yaw=π，报告增加view_convention=right-handed-view-v2，避免混用旧视角结果。旧报告和文件备份保留在output/sam3d_cloud/orientation_backup/。
